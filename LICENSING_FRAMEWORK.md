# Licensing Framework

This file records the intended legal architecture for Citrate.

The operative repository terms are now expressed in the root [LICENSE](../LICENSE), [PATENT_NOTICE.md](../PATENT_NOTICE.md), and [TRADEMARK_POLICY.md](TRADEMARK_POLICY.md). This file remains the canonical product-intent explainer for how those rights are structured.

## Goal

Make Citrate:

- easy to learn from
- safe to fork for education and research
- available for small private networks
- protected against unlicensed commercial extraction

## Recommended Structure

### Source-available code license

The repo now uses a source-available license with an explicit Additional Use Grant for:

- education
- research
- internal evaluation
- classrooms
- labs
- small private learning networks

Commercial use should not be granted by default.

### Commercial license

Mozi Cooperative should separately license:

- production deployments
- public network launches
- hosted infrastructure and APIs
- branded wallets or apps
- institutional rollouts
- white-label derivatives

### Trademark policy

Brand, marks, logos, and product identity should remain reserved unless explicitly licensed.

### Patent / provisional review

If the team wants protection over mechanism-level innovation, review provisional patent options for:

- consensus extensions
- AI precompile interfaces
- ZK verifiable compute flows
- embedded-node + local-agent orchestration patterns

### Contributor agreement

Use a CLA or assignment model that gives Mozi Cooperative clean relicensing rights.

## Important Constraint

Copyright alone will not protect abstract consensus or protocol ideas.

To protect the full stack, combine:

- copyright
- trademarks
- contracts
- contributor agreements
- patent strategy where appropriate
