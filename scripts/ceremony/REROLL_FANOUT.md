# Fresh-Keys Reroll — Consumer Fan-Out

**Owner ruling + MAC audit (citrate-security).** The fresh-keys reroll keeps
`chainId = 40204` but deploys the whole stack from brand-new keys, so **~57
addresses move** (every key-derived contract + the fresh EOAs). This is the
authoritative list of every consumer/config that pins 40204 addresses and MUST
be re-fanned after the reroll. Nothing here is edited by the reroll PR itself —
this is the post-ceremony punch-list.

Regenerate the canonical table first:

```bash
bash scripts/ops/emit-address-table.sh          # → contracts/addresses/40204.json
bash scripts/ci/check-create2-determinism.sh    # gate: addresses reproducible
```

Then fan out `contracts/addresses/40204.json` (+ the fresh EOAs) to each repo below.

## Note — which addresses actually MOVE
- **MOVE (key-derived):** everything governed by `GOVERNANCE`/`GUARDIAN`/deployer
  (all DeployAll contracts), `ValidatorRegistry` (governance_/slasher_),
  CoreMembership `CitrateMemberSBT` + vault proxy (owner + registry args),
  AA `CitrateWalletFactory` + `CitratePaymaster` (owner/identity/sponsor args),
  and the three ex-kept-live registries (now fresh, multisig-governed).
- **DO NOT move (bytecode-only / fixed):** Arachnid factory `0x4e59…4956C`,
  EntryPoint, `GuardianRecoveryModule`, `CitrateWallet` impl, `MemberBond`,
  `MembershipStakeVault` implementation, P256 verifier `0xc2b7…De4`,
  `AIModelRegistryPortable` (no key args). These are unchanged bytecode anchors —
  re-verify with `check-create2-determinism.sh` but they keep their addresses.
