## Genesis — how it actually works

The chain genesis is **deterministic and hardcoded in Rust**:

- [`node/src/genesis.rs`](../src/genesis.rs) — `GenesisConfig::default()` defines initial accounts; `CANONICAL_GENESIS_TIMESTAMP = 2026-01-01T00:00:00Z UTC` makes the genesis block hash byte-identical across independent startups.
- [`core/economics/src/genesis.rs`](../../core/economics/src/genesis.rs) — `EconomicsGenesisConfig::testnet_beta()` / `::mainnet()` / `::default()` / `::team_testnet_genesis()` profiles, selected by chain ID at startup.

A node starts, looks at `[storage].data_dir`, and:
- **If a genesis block exists in storage** → resume.
- **If not** → call `initialize_genesis_state_with_profile()` with the chain-ID-appropriate profile, write the deterministic block 0, then start mining.

**There is no `genesis.json` file consumed at runtime.**

If you need a JSON snapshot of the canonical genesis for audit / inspection purposes, dump it from a running node:

```bash
# After a fresh node start:
curl -s -X POST http://127.0.0.1:8545 \
    -H 'content-type: application/json' \
    -d '{"jsonrpc":"2.0","method":"eth_getBlockByNumber","params":["0x0",true],"id":1}' \
    | jq '.result' > /tmp/genesis-block-0.json
```

Or invoke the in-Rust dump path:

```bash
cargo run --release --bin citrate-node -- --config node/config/testnet-beta.toml --genesis-info
```

## Bootnode peer-ID embedding

`testnet-beta.toml` carries `bootstrap_nodes = [...]` entries in **trusted form**:

```
"noise_<hex>@<host>:<port>"
```

These are pre-generated by [`core/network/examples/gen_bootnode_keys.rs`](../../core/network/examples/gen_bootnode_keys.rs). The matching `noise.key` files are uploaded to each DigitalOcean bootnode at provisioning time so the live peer ID matches the baked-in identity. See [`tools/bootnode-keys/README.md`](../../tools/bootnode-keys/README.md) for the keypair lifecycle.

## Editing a config

- TOML schema lives in `node/src/config.rs` (`Config` struct + nested types).
- Adding a new field: update the struct + `Default` impl, then propagate to every config in this dir or the relevant subset.
- Cross-network behavior differences should live in code (selected by chain ID), not in config — configs are operator-overrides, not behavior switches.
