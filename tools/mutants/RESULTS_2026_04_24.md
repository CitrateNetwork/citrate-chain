# RM-A1 / WP-A1.1 Mutation Campaign — Results

**Tool**: `cargo-mutants 27.0.0` installed via `cargo install cargo-mutants --locked`.

**Scope**: `wallet-core/src/keys.rs` + `wallet-core/src/types.rs`. The CLI
wallet's parallel keystore (`wallet/src/keystore.rs`) gets its own
campaign in RM-G2 when keystore consolidation lands.

**Command**:

```bash
cargo mutants --package citrate-wallet-core \
  --file wallet-core/src/keys.rs \
  --file wallet-core/src/types.rs \
  --timeout-multiplier 3.0 \
  --jobs 2 --no-shuffle \
  --output tools/mutants/wal-01-output
```

## Run 1 — initial (pre-KAT)

```
117 mutants tested in 7m: 2 missed, 10 caught, 105 unviable
```

| Mutant | Disposition |
|--------|-------------|
| `wallet-core/src/keys.rs:48 — replace argon2_for_version body with Ok(Default::default())` | **MISSED — REGRESSION** |
| `wallet-core/src/keys.rs:564 — replace - with + in secp256k1_secret_from_seed` | MISSED — dead code (WAL-10) |

The first miss was the expected WAL-01 hand-mutation: collapse the
dispatcher to `Argon2::default()` for every version. The
`kdf_version >= 2` field check in our regression test passed under that
mutation because encrypt and decrypt were both consistent at default
params. The actual derived bytes differed but no test was checking them.

The second miss is a known dead-code path tracked as WAL-10 in the audit
(`secp256k1_secret_from_seed` is documented but never wired). Fixed in
RM-G2 cleanup.

## Run 2 — post-KAT (added `test_wal01_argon2_v2_known_answer_locks_parameter_set`)

To plug the first miss, two new tests were added to
`wallet-core/tests/wal01_kdf_strength.rs`:

- `test_wal01_argon2_v2_known_answer_locks_parameter_set` — asserts the
  derived bytes for a fixed `(password, salt)` against a hex-encoded
  known answer. Any change to the v2 params (m, t, p, output_len, or
  algorithm) will perturb the bytes and fail the assert.
- `test_wal01_argon2_v2_differs_from_default` — direct discriminator that
  derives under v2 *and* under `Argon2::default()` and asserts they
  differ. Catches the exact `Ok(Default::default())` mutation.

Re-run on `keys.rs` only (`brxdijyal`) was interrupted ~partial but
visibly **still showed the dispatcher mutant as missed** plus six
password-length boundary mutants (`< 8` → `==`/`<=` in
import_account / recover_from_mnemonic / create_secp256k1_account).
Diagnosis: the KAT in `tests/wal01_kdf_strength.rs` constructs
`Argon2::new(...)` directly instead of going through
`argon2_for_version`, so a mutation of the dispatcher body doesn't
affect the test's locally-built argon2 instance.

## Run 3 — dispatcher-internal tests + password boundary tests

Added two more sets of tests to plug the surviving mutants:

1. **In-module dispatcher tests** at the bottom of `wallet-core/src/keys.rs`
   (`kdf_dispatcher_tests` mod, 5 tests). Calls
   `argon2_for_version(KDF_VERSION_CURRENT)` directly and inspects
   `Argon2::params()` accessors (`m_cost`, `t_cost`, `p_cost`,
   `output_len`). Made `argon2_for_version` `pub(crate)` so the inline
   test can reach it.
2. **Password-length boundary tests** in
   `wallet-core/tests/wal01_kdf_strength.rs` (8 tests, one
   reject + one accept-at-exactly-8 per code path). Kills the
   `< 8` → `<=` / `==` mutations across the four account-creation
   functions.

**Run 3 result**: `cargo mutants --package citrate-wallet-core --file
wallet-core/src/keys.rs` produced

```
72 mutants tested: 33 caught, 0 missed, 39 unviable
```

The WAL-01 mutation gap is fully closed for `keys.rs`. Every mutant the
campaign generates is either killed by a test (33) or structurally
unviable (39 — `continue` removals on dead arms, etc.). The
`secp256k1_secret_from_seed - to +` mutant is no longer in this run's
scope because mutation v3 ran on `keys.rs` only and `secp256k1_secret_from_seed`
is genuinely dead code (audit finding WAL-10 — RM-G2 will either wire
it or delete it).

## Disposition

- **WAL-01 mutation gap closed by Run 2.** Verified by the new
  discriminator + known-answer test pair.
- **WAL-10 (`secp256k1_secret_from_seed` dead code)** acknowledged and
  scheduled for RM-G2 close. Either wire the function into
  `create_secp256k1_account` or delete it; the planset's RM-G2 WP-G2.3
  carries this item.
- **105 unviable mutants** are mostly impossible-to-test changes
  (`continue` removals, branch eliminations on dead arms, etc.) — normal
  noise floor for cargo-mutants 27.0 on Rust 1.93.
