# CL-C2 — One source of truth for chain-40204 addresses + drift enforcement

## Problem (from the 2026-07-27 federation sweep)

Reroll address-drift is **one missing control manifesting across 13 repos**, not 13
bugs. After the 2026-07-27 canonical reroll, ~13 repos vendor stale contract addresses
and the CI drift-gates that should catch it are absent, self-referential (a tautology
comparing a copy to itself), or not wired into CI. There is no shared typed source; the
canonical `contracts/addresses/40204.json` is copied by hand-rolled per-repo
`sync-addresses` scripts of varying quality. Every reroll silently breaks money-path and
read-path code federation-wide. The nonce-based `CitrateMemberSBT` / `MembershipStakeVault`
move on *every* reroll (see reroll-membership-contracts-drift), so this is recurring.

## Decision

- **Canonical source stays** `citrate-chain/contracts/addresses/40204.json`, regenerated by
  `scripts/ops/emit-address-table.sh` after each reroll ceremony. No change.
- **Publish a typed distribution**, `@citratenetwork/chain-config`, generated from that JSON.
  Consumers **import** it (typed) instead of vendoring raw JSON.
- **Standardize the drift gate**: a single `check` CLI (`citrate-chain-config check <file>`,
  exit 1 on any missing/mismatched address, checksum-insensitive) replaces every bespoke,
  self-referential per-repo check. Blocking, not `continue-on-error`.
- **Boot-time `getCode` verify** is mandatory for the two nonce-based singletons in any repo
  that reads them (SBT/vault), because a matching pin is necessary but not sufficient —
  they can be undeployed after a reroll.

## Scope decisions locked

- D1: package name `@citratenetwork/chain-config` (matches README's `@citratenetwork/sdk`).
  Confirm registry scope vs the published `@citratelabs/*` before first publish (WP-2 gate).
- D2: package lives in `citrate-chain/packages/chain-config` (source-adjacent so the
  generator reads the sibling JSON; keeps one repo owning source + distribution).
- D3: dependency-free (Node built-ins only) so it adds no toolchain to the ToB-scoped repo
  and every consumer (JS/TS) can run the gate with `npx` and no install.
- D4: Rust consumers get a parallel `citrate-chain-config` crate in a later WP (native,
  node-agent, boeing-shell, bundler read addresses from Rust).
