# I64-S1 Phase A — chain-wide Q16 i32 → i64 unification

The consensus-code half of a program that makes the chain's on-chain fixed-point
arithmetic agree, bit-for-bit, with the Tier-1-audited `citrate-fed-types` kernel —
so a precompile result and the off-chain gradient path can never disagree. Folded
into the deterministic state-reset reroll, which is what makes it cheap: a fresh
genesis runs i64 from block 0, so there is **no hardfork height, no dual-format
window, no state migration**, and — because i64 lives in the node binary /
precompiles / genesis and not in CREATE2 init-code — **every existing contract
address is preserved**.

## How this started (and why the audit "missed" it)

The task was supposed to be "adopt the audited kernel Q16 on the chain side." It
wasn't, because the chain was already running a *different* Q16: an `i32` newtype in
the execution precompiles, while the kernel and nat had widened to `i64`. The Tier-1
audit hadn't caught the discrepancy because its scope was kernel↔nat faithfulness,
not kernel↔chain *integration* — the gap only exists at the seam the audit didn't
cross. An Explore pass had also claimed the two types were "byte-identical"; refusing
that claim and reading the actual struct (`pub struct Q16(pub i32)` vs `Q16(i64)`)
is what surfaced the real shape of the work. **Reproduce-or-retract earned its keep
on the first hour.**

The fork in the road — keep i32, or commit to i64 — resolved to i64 once it was clear
that (a) i64 only *adds* integer headroom (±32_768 → ±1.4e14) at the *same* 2⁻¹⁶
resolution, so nothing that fit before is lost, and (b) folding it into the reroll
erased the entire hardfork apparatus the change would otherwise have needed.

## What the consumer audit (A6) actually was: the hero of the sprint

A6 was framed as a one-line `.sol` grep for address safety. In practice it was the
mechanism that kept the sprint honest, because it surfaced two consensus surfaces the
planset never enumerated:

1. **The tensor precompile family (`0x010A–0x010F`, `tensor_format`/`compute`).** A
   *second* Q16 wire format (little-endian, separate from belnap/routing's big-endian),
   feeding matmul/dot/softmax/linear. A subagent had kept it compiling with an interim
   `q.0.clamp(i32::MIN, i32::MAX)` on encode — a **silent corruption** of any
   over-i32-range output. Caught, surfaced, removed.
2. **The halo2 inference-proof circuit (`0x0105`).** The LinearChip recovers operands
   from field elements *as i32* and multiplies them *as i64* — which only fits because
   it assumes i32-range inputs (max |W·x| < 2⁶²). Under i64 Q16 the raw product reaches
   ~2e28 and overflows i64 catastrophically. A genuine i32 hard-lock buried three layers
   into a zk circuit, invisible to a grep.

Both became owner decisions (full unification; widen the circuit) rather than silent
calls — exactly because they change the reroll's attack surface.

## What worked

- **Blast-radius triage as a first-class rule.** Pure arithmetic width = no new attack
  vector → parity-test only. Wire-format deserializers = real attack surface → full
  adversarial fuzz. That single distinction told us where to spend rigor: the belnap/
  routing fuzz harnesses are format-agnostic (`fuzz_target!(|data: &[u8]|)`), so the
  100k/50k deterministic sweeps + proptests re-proved panic-freedom on the *new* 8-byte
  decoders with zero new test code.
- **One atomic execution-crate change.** Widening `mod.rs` cascades immediately into
  belnap/routing wire reads — the crate won't compile until every byte-offset moves
  together. Treating it as one unit (not a staged half-migration) avoided a window of
  inconsistent decoders.
- **Golden re-freeze by sentinel-and-read.** For the two exp values that moved from
  "gate-saturated" to "representable," writing a deliberate-wrong sentinel and letting
  the fixture test's own mismatch reporter print the real bytes beat hand-computing
  `e¹¹ · 2¹⁶`. exp(16) = 582_362_333_184 raw is > i32::MAX — proof the value genuinely
  needed i64, not just that it *fit*.
- **The zkp finding inverted a decision the right way.** I'd planned to bump
  `CIRCUIT_VERSION_LINEAR_Q16`. Reading the gates showed they're all field-exact
  algebraic relations with *no* bit-range gates → the constraint system, and therefore
  the verifying key, is byte-identical. A version is a VK registry key; bumping it would
  imply a VK that doesn't exist (and collide with the already-reserved v4/v5). Kept v1,
  documented at the anchor. Implementation contradicting the plan, surfaced not buried.

## What didn't / what surprised

- **The kernel MSRV (1.96) is ahead of the chain's stable (1.93).** The parity test
  imports both Q16 types, so it can't live in the consensus build without dragging the
  whole workspace onto a newer toolchain + a private git dep. Resolved by making
  `core/federated` an **excluded** crate (own workspace, run with `+1.96.0`), so
  `cargo build --workspace` is untouched — but it's a real integration seam the program
  will have to reconcile before chain and kernel share a toolchain.
- **exp's saturation boundary was a semantic trap.** Under i64, the old `x ≥ 11 → MAX`
  gate would have made exp(11) return 1.4e14 instead of ~59874 — *worse* than the old
  saturation. The gate had to move to the true i64 overflow (~x=34), which also means
  the high range is now exercised territory the monotonicity proptest never covered
  (left at its verified range; determinism fixtures cover the rest — noted, not hidden).
- **Two pre-existing `ai_opcode_e2e` failures** (`addr[17]` vs the namespace nibble at
  `addr[18]`) are unrelated to this work and were left out of the diff rather than
  silently "fixed" — they predate the branch.

## Honest scope (what Phase A is NOT)

This is the consensus *code* change only. It does not deploy anything, does not touch
the reroll state reset, and does not re-run the load benchmark (that needs a live node
and sequences with bring-up). Phase B (contracts + coop) and Phase C (the actual
reroll + funding) are separate and gated. The kernel-parity crate proves agreement but
runs out-of-band on a newer toolchain — wiring chain and kernel onto one toolchain is
deferred, deliberately.
