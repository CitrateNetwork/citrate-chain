# Producer operator onboarding checklist (for the owner)

Use one copy of §2 per operator. The goal for rehearsal 1 (2026-11-13) is **at least four producers on separate hosts and separate operators**, registered and staked. The operator does the work in [`PRODUCER_OPERATOR_RUNBOOK.md`](PRODUCER_OPERATOR_RUNBOOK.md). This file lists what to ask them for and what to decide. Keep names, contacts and agreements in the private federation repo, not here.

## 1. Decisions before asking anyone

- [ ] **Who the four (or more) operators are.** Separate means a different person or organization, a different cloud account and provider region, and no shared administrators. The four DigitalOcean fleet nodes are one operator (us). They count as **one** producer toward the four, however many of them produce.
- [ ] **A named alternate per operator**, in case one drops out in the week of 2026-11-09 or over Thanksgiving week.
- [ ] **Stake per producer.** The registry's minStake is 32,000 SALT. The C2 genesis spec (D2/D7) allocates about 32,100 SALT per operator staker (stake plus gas), generated by the operator. Confirm the amount, and whether operators bond only the allocation or add their own.
- [ ] **Terms.** What we ask of an operator (uptime, upgrade window, incident contact, exit notice) and what they get (block rewards accrue to their staker; this runbook makes no yield claims, per UI truth contract §5). Counsel to review if money or a contract is involved.
- [ ] **Bootnode role.** Whether any operator should also serve as a bootnode. If yes, its Noise peer ID goes into the rehearsal profile's `bootstrap_nodes`.

## 2. Ask each operator for

### Identity and contact

- [ ] Operator name (person or organization) and a second contact
- [ ] An incident channel that reaches a human within 1 hour during 2026-11-12 → 2026-11-14 (rehearsal 1), 2026-11-24 (rehearsal 2) and 2026-12-01 (genesis)
- [ ] Time zone and availability over 2026-11-23 → 2026-11-28
- [ ] Agreement to: never share or copy the proposer key, never run it on two hosts, report a suspected compromise to security@citrate.ai first, and give notice before exiting

### Host (runbook §1–2)

- [ ] Provider, region and account. These must differ from every other producer's
- [ ] Architecture (x86_64 or aarch64), vCPU, RAM, disk size and type
- [ ] Public IP or DNS name with **TCP 30303 open inbound**
- [ ] **`preflight.py` output** with no FAIL lines (`sudo python3 scripts/producers/preflight.py --profile 40204-r1005`). For rehearsal 1, rerun it with `--profile rehearsal-1` once that profile is ready
- [ ] Confirmation that nobody builds software on the host, and that SSH is key-only

### Keys (runbook §4–5): public values only

- [ ] **Staker address** (`0x…`), generated by the operator on a hardware wallet (preferred) or an offline machine. It is also the node's coinbase. Never accept a private key, a seed phrase or a keystore file. If one is sent, treat it as compromised and ask for a new address
- [ ] **Proposer public key** (`0x…`, 32 bytes), from `citrate-node --config /etc/citrate/node.toml registration-proof --registry <ValidatorRegistry>` after the node's first start
- [ ] Confirmation that `proposer.key` and `noise.key` are backed up (encrypted, offline, two copies)
- [ ] The node's Noise peer ID, only if it will serve as a bootnode

### Software (runbook §3)

- [ ] The installed release tag, and the `citrate-node consensus` fingerprint they see (it must equal the announced one)
- [ ] The watchdog installed, with the alert hook pointing at their on-call (`citrate-watchdog-ctl.sh status` output, showing `ACTIVE`)

## 3. Chain-team actions per operator, in order

| # | Action | Evidence |
|---|---|---|
| 1 | Review the preflight output; resolve FAIL and WARN lines with the operator | Preflight output on the tracking issue (no IPs in public) |
| 2 | Put the staker address in the genesis allocations (C2 D2) for the rehearsal genesis, or fund it by transfer on 40204 for a dry run | Allocation table / tx hash |

| 4 | Operator generates config, starts with mining off, syncs | Their `eth_syncing` = false |
| 5 | Operator runs `build_registration_tx.py`, signs with their wallet, publishes | Registration tx hash |
| 6 | `verify_producer.py --staker <addr> --require registered` | "Registered · active from epoch N" |

| 8 | Operator turns mining on; `verify_producer.py --staker <addr>` passes all five checks | "Producing blocks" |
| 9 | Network check: the verifier's `producing_validators` ≥ 4 over a 1,000-block window, and `--require committee` exits 0 (`committee_qualifying_members` ≥ `min_finality_committee`) | Its JSON output on the C3 board item |

## 4. Timing back from rehearsal 1 (2026-11-13)

| By | What |
|---|---|
| 2026-10-30 | Operators and alternates named. C2 decisions (D2 allocations, D7 producers) made |
| 2026-11-03 | Every operator has a host passing preflight against `40204-r1005`, and has sent a staker address |

| Genesis cut for rehearsal 1 | Staker addresses in the genesis allocations; `rehearsal-1` profile filled and released |
| Rehearsal day | Start (mining off) → register right after genesis → active at the first epoch whose snapshot follows the registration (200 to 1,200 blocks, about 7 to 40 min) → mining on → ≥ 4 producing |

Note for the genesis cut: the chain needs at least one registered producer before `CITRATE_VALIDATOR_ACTIVATION_HEIGHT`, or nothing can produce once membership is enforced. The genesis producer registers first (seeded at genesis, or in the first blocks before S(1) = 800). Operators register after it and join at epoch boundaries.

## 5. What is not ready yet (claim honesty)

- Checkpoint finality is **not running** on any network. The producer half (PR #321) is in review with its switch compiled OFF. Four producers is the precondition for turning it on, not proof that it runs.
- No RPC exposes the consensus snapshot or the checkpoint committee. `verify_producer.py` **derives** committee membership from the registry rule and says so in its output.
- The `rehearsal-1` profile is `pending-genesis`. Every tool refuses it outside `--dry-run` until the chain team fills it.
